UIM Utilities · feature design

Left-click the pile and get what you wanted

Rebagging drops a bag's worth of items on the floor in no order at all. This is a plan for making the pile come back in an order you chose, and the decisions I need from you before any of it is written.

Nothing built yet

01 The problem

The pile arrives in arbitrary order, so taking what you actually want means reading twenty-odd Take lines and right-clicking through them one at a time, holding the order in your head as you go. The goal is to spam left-click instead.

02 How rebagging actually works

  • Destroying the bag in the Wilderness drops the contents on the floor. Anywhere else, Ferox Enclave included, the contents are destroyed permanently.
  • The pile lasts 60 minutes, counted only while logged in, and in the Wilderness it is visible to everyone immediately. Sorting has to be fast, not merely convenient.
  • Deathpiling is the alternative and produces the same problem: a pile in arbitrary order.

03 This collides with a feature we already shipped

Decision 1

The looting bag feature removes Destroy. Rebagging is destroying the bag on purpose.

ARemove Destroy only outside the Wilderness, where it deletes items, and leave it alone inside, where it is the intended move. The rule then matches the game's own behaviour.
BKeep the removal unconditional and let the player toggle the setting off to rebag.

A is better protection and better ergonomics, but it is conditional menu entry removal, which the hub's rejected-features page is wary of. B is safe with reviewers and mildly annoying twice a week.

04 The mechanism, and who has done it already

Settled, with precedent on both sides of the hub line.

  • client.getMenuEntries() is an array where index 0 is the bottom of the menu and the last element is the top, which is the left-click action. Reordering the array reorders the menu.
  • Ground item entries are the menu types from WIDGET_TARGET_ON_GROUND_ITEM through GROUND_ITEM_FIFTH_OPTION, and getIdentifier() on one is the item id.
  • Core precedent: RuneLite's own Ground Items plugin rewrites the whole entry array every client tick to collapse duplicates and append x N to their names.
  • Hub precedent: geheur's more-menu-entry-swaps sorts ground item entries by price. It finds each contiguous run of them, sorts that run, and writes it back in place, leaving every other entry untouched. This feature is that, with a category rank instead of a price.

Sorting is a swap rather than a removal, so it sits on the accepted side of the hub's menu rules.

05 Where a category comes from

The interesting question, because a hardcoded list of every item in the game is not maintainable and the hub rejects raw ids as config input. Three sources, in precedence order.

SourceWhat it can tell usCatch
Your listA name list per category, comma separated, * wildcards, exactly like the shop feature's protected list.None. Always wins, and covers whatever the other two get wrong.
Item actionsgetInventoryActions() holds Eat for food and Drink for potions.None. Local and instant.
Equipment statsSlot and attack bonuses. Whichever of amagic, arange or the melee bonuses dominates says what a piece is, so a Bandos chestplate classifies itself.Fetched over the network at startup, so it can be missing early or absent offline. Must fall back rather than misfile.
Name patternsRunes, herbs, seeds, logs, bars.Crude, but it is the floor under the other two.

Anything still unclassified lands in one bucket you can position, rather than being dropped to the bottom silently.

06 How you set the order

You asked for drag and drop. That means a side panel, which is a bigger build and a bigger review surface, so I would stage it.

  • First: an ordered, comma separated category list in the config. The order is the text. Editable, hub-friendly, no new UI.
  • Later: a panel with drag to reorder, once the category model has proven itself in a real rebag. Deathbank-utility already ships a panel, so there is a pattern to copy.

07 You already run another sorter

Decision 2

geheur's plugin sorts the same ground item block on the same event.

Two plugins sorting one array means last writer wins, and the order looks random depending on subscriber order. This needs deciding rather than discovering.

ASet an explicit subscriber priority so this plugin sorts last.
BDetect that plugin's ground item sort and stand down while it is on.
CDocument that its price sort should be turned off.

Core's Ground Items collapse feature also rewrites entries, on a different event, and appends x N to names. Any name matching has to tolerate that suffix either way.

08 To verify before building

That the last array element really is the left-click entry, seen in a real pile rather than inferred.
Whether the client caps how many entries a menu can hold, since a rebag pile is large.
Whether ground item entries are always one contiguous run, or several.
Whether the equipment stats are loaded by the time a rebag happens, and what fraction of a real bag they classify unaided.
What a full inventory does: only stackables you already hold can be taken, so the sort should not put an untakeable item on left-click.
